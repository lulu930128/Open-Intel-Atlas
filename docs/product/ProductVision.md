# 產品願景

## 文件狀態

- `已確認`：來自使用者本次需求或目前 repo 的明確產品描述。
- `目前假設`：可安全推進，但仍可由使用者調整。
- `待決策`：會影響後續實作順序或產品邊界，尚未定案。

## 最終產品一句話

`已確認` Open Intel Atlas 是一套可長期擴充的新聞與公開情報系統：持續蒐集多領域公開來源，把內容整理成可追溯的故事、事件與摘要，透過 UI、versioned API 與 MCP 同時服務人與其他系統。

## 核心範圍

第一級主領域為：

1. 政治：國內外政治、政策、選舉、外交、衝突與地緣政治。
2. 科技發展：AI、軟硬體、研究、資安、太空與重大技術進展。
3. 金融：總體經濟、金融市場、公司與產業事件；不取代即時行情或交易系統。
4. 氣象與重大天災：官方氣象警報、地震、颱風、洪水、野火、火山及其他重大災害。

`已確認` 上述項目是主要入口，不是封閉清單。醫療、公共衛生、能源、社會、環境等領域可透過分類註冊表擴充，不應為每個新領域重寫核心流程或建立一套新的 API。

## 核心使用者

- `已確認` 專案擁有者：透過 UI 快速了解最新狀況、資料來源、時間、可信度與變化。
- `已確認` OMI：取得可追溯的新聞／事件證據，作為市場研究的外部情境；市場語意與投資判斷仍由 OMI 負責。
- `已確認` Kuro 桌寵：取得精簡且來源透明的摘要或提醒；人格、對話語氣與通知體驗仍由 Kuro 負責。
- `目前假設` 其他本機 agent 或應用：透過 read-only API/MCP 查詢 brief、story、event 與 source health。
- `待決策` 是否服務網際網路上的第三方開發者，以及是否需要多使用者帳號、配額與商業方案。

## 核心工作流

1. 開啟首頁後，先看到跨領域的重大故事、資料時間與來源覆蓋狀況。
2. 從摘要進入單一 Story，查看事件時間線、不同來源、官方證據、修正與不確定性。
3. 依領域、主題、實體、地區、時間、嚴重程度與驗證狀態搜尋或篩選。
4. 檢查來源健康度、最後成功時間、缺口與降級原因，判斷目前畫面是否可信。
5. 由 OMI、Kuro 或其他 agent 透過穩定 API/MCP 取得同一套 canonical evidence 的不同投影。

## 第一屏必須成立的體驗

第一屏不是單純新聞卡片牆，也不是只有世界地圖。它應在不打開細節前回答：

- 現在最值得注意的是什麼？
- 事件發生在哪裡、何時發生、目前是否仍在發展？
- 這是單一媒體報導、官方資訊，還是已有獨立來源交叉佐證？
- 哪些主領域目前資料正常，哪些來源 stale、partial、disabled 或 failed？
- 點進去後，能否回到原始來源而不是只看到系統自己生成的結論？

## 長期不做的事

- 不成為新聞全文鏡像站；預設保存 metadata、短摘錄、內容 hash 與原文連結。
- 不把每一篇文章、每一次市場價格變動或每一篇研究論文都自動升格為重大事件。
- 不把「有新聞」誤寫成「已證實」，也不把 aggregator 的多筆結果誤算成多個獨立來源。
- 不替 OMI 產生投資建議、交易訊號或市場真相；Atlas 只提供外部事件證據與清楚限制。
- 不替 Kuro 決定人格、對話語氣或使用者通知政策。
- 不把 LLM 摘要當作 canonical evidence，也不允許 UI 或 MCP adapter 重新計算核心可信度與嚴重度。

## 必須反駁的方向

- 為了快速新增領域而持續擴充 hard-coded category array 或一類別一個 DB。
- 由瀏覽器、OMI 或 Kuro 直接抓第三方新聞來源，繞過 Atlas 的來源政策、去重與 lineage。
- 只顯示一個模糊的 confidence 百分比，卻沒有來源數、來源獨立性與驗證狀態。
- 公開 API 後才補 authentication、rate limit、授權與內容再散布政策。
- 用來源抓取成功取代 UI 可見、API contract、MCP protocol 與消費端實際採用的分層驗證。

## 待決策

- 初期只限本機／內網，或需要直接對公網提供服務。
- 繁體中文、英文與多語內容的顯示、翻譯與搜尋優先順序。
- 通知延遲目標：分鐘級 near-real-time、每小時 digest，或每日 brief。
- 原始 payload、文章 metadata、Story 與 Event 的保存期限。
- LLM 的角色是否只做可選摘要，或也參與分類、實體抽取與 Story clustering。
